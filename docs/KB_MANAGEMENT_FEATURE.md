# Управление базой знаний: загрузка файлов и переиндексация

Спецификация фичи «Управление БЗ» — веб-страница для менеджера колл-центра с загрузкой PDF и запуском переиндексации векторной базы Qdrant.

---

## 1. Обзор

Менеджер колл-центра открывает страницу управления базой знаний (`/admin/kb`), где может:

1. **Загрузить новый PDF** — файл сохраняется как `kb/KB.pdf`, старый файл уходит в бэкап.
2. **Запустить переиндексацию** — пересобрать векторную базу в Qdrant из загруженного PDF.
3. **Видеть дату последнего обновления** — когда БЗ была загружена/проиндексирована.

Адрес: `http://localhost:8000/admin/kb`

---

## 2. API эндпоинты

### 2.1 `POST /UploadFile`

Загрузка PDF-файла базы знаний.

**Запрос:**

| Поле   | Тип          | Обязательно | Описание |
|--------|--------------|-------------|----------|
| `file` | File (PDF)   | Да          | PDF-файл базы знаний |
| `name` | string (Form)| Да          | Имя файла (передаётся веб-интерфейсом всегда KB.pdf) |

**Валидация (сервер):**

| Проверка | Условие | Ошибка |
|----------|---------|--------|
| MIME-type | `application/pdf` | 400: «Допустимы только PDF-файлы» |
| Magic bytes | Файл начинается с `%PDF` | 400: «Файл не является PDF» |
| Размер | ≤ 20 МБ | 400: «Файл слишком большой (макс. 20 МБ)» |
| Читаемость | `pdfplumber.open()` не падает | 400: «PDF повреждён или не читается» |

**Логика:**

1. Валидация файла (mime, magic bytes, размер, читаемость).
2. Если `kb/KB.pdf` существует → переименовать в `kb/KB_backup.pdf` (хранится 1 бэкап).
3. Сохранить загруженный файл как `kb/KB.pdf`.
4. Обновить дату загрузки в `kb_hash.json` (поле `upload_date`).

**Ответ (200):**

```json
{
  "status": "success",
  "name": "KB.pdf",
  "date": "09.02.2026 12:18"
}
```

**Ошибки:**

| Код | Описание |
|-----|----------|
| 400 | Невалидный файл (тип, размер, повреждён) |
| 401 | Не авторизован |
| 500 | Ошибка сохранения файла |

---

### 2.2 `POST /IndexDB`

Запуск переиндексации векторной базы Qdrant из `kb/KB.pdf`.

**Запрос:** без параметров (тело не требуется).

**Логика:**

1. Проверка: файл `kb/KB.pdf` существует.
2. Проверка: Qdrant и BGE-M3 доступны.
3. Проверка: переиндексация не запущена (lock `indexing_in_progress`).
4. Установить lock.
5. Создать новую коллекцию `kb_v1_{timestamp}`.
6. Запустить `index_knowledge_base()` (PDF → чанки → эмбеддинги → Qdrant).
7. Переключить alias `kb_current` на новую коллекцию.
8. Пересоздать `bm25_index` в памяти из новых чанков.
9. Обновить `kb_index_ready = True`.
10. Обновить дату индексации в `kb_hash.json` (поле `index_date`).
11. Снять lock.

**Ответ (200):**

```json
{
  "status": "success",
  "date": "09.02.2026 12:20"
}
```

**Ошибки:**

| Код | Описание |
|-----|----------|
| 401 | Не авторизован |
| 404 | Файл `kb/KB.pdf` не найден. Сначала загрузите файл |
| 409 | Индексация уже выполняется |
| 503 | Qdrant или BGE-M3 недоступны |
| 500 | Ошибка индексации |

---

### 2.3 `GET /kb/status`

Состояние базы знаний (для отображения на странице).

**Ответ (200):**

```json
{
  "file_exists": true,
  "file_name": "KB.pdf",
  "file_size_mb": 2.4,
  "upload_date": "09.02.2026 12:18",
  "index_date": "09.02.2026 12:20",
  "index_ready": true,
  "indexing_in_progress": false,
  "backup_exists": true
}
```

## 3. Авторизация

Эндпоинты `/UploadFile`, `/IndexDB`, `/kb/status` и страница `/admin/kb` защищены **HTTP Basic Auth**.

| Параметр | Источник | Значение по умолчанию |
|----------|----------|-----------------------|
| `ADMIN_USER` | `.env` | `admin` |
| `ADMIN_PASSWORD` | `.env` | (обязательно задать) |

Реализация — FastAPI `HTTPBasic`:
- При первом обращении браузер показывает стандартное окно ввода логина/пароля.
- Сравнение через `secrets.compare_digest` (защита от timing-атак).
- Основные эндпоинты бота (`/process_message`, `/escalate`, `/health`) остаются без авторизации.

## 4. Веб-страница `/admin/kb`

Одностраничное HTML-приложение, обслуживается через FastAPI `StaticFiles`.

### 4.1 Элементы интерфейса

```
┌─────────────────────────────────────────────────────────┐
│  Управление БЗ                                          │
│                                                          │
│  Дата последнего обновления базы знаний: dd.mm.yyyy HH:mm│
│                                                          │
│  ┌──────────────────────────────────────────┐            │
│  │  📄 File Picker                          │            │
│  │  Допустимые форматы: PDF                 │            │
│  │  Максимальный размер: 20 МБ              │            │
│  └──────────────────────────────────────────┘            │
│                                                          │
│  [ Загрузить файл ]    [ Проиндексировать базу знаний ]  │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### 4.2 FilePicker (ограничения на фронте)

| Ограничение | Реализация |
|-------------|------------|
| MIME-type | `<input type="file" accept=".pdf,application/pdf">` |
| Размер | JS-валидация: `file.size <= 20 * 1024 * 1024` |

Фронтовая валидация — для UX (мгновенная обратная связь). Серверная валидация — обязательна (фронт обходится).

### 4.3 Поток «Загрузить файл»

1. Менеджер выбирает PDF через FilePicker.
2. Нажимает «Загрузить файл».
3. Модальное окно: **«Загрузить базу знаний? [Нет] [Да]»**
4. При «Да» → `POST /UploadFile` (с `file` и `name: KB.pdf`).
5. Успех → уведомление: **«База знаний загружена. Проиндексируйте базу знаний!»** [OK]
6. Обновить дату на странице из поля `date` ответа.
7. Ошибка → уведомление с текстом ошибки.

### 4.4 Поток «Проиндексировать базу знаний»

1. Менеджер нажимает «Проиндексировать базу знаний».
2. Модальное окно: **«Проиндексировать базу знаний? [Нет] [Да]»**
3. При «Да» → `POST /IndexDB`.
4. Показать индикатор загрузки (индексация может занимать 30–120 с).
5. Успех → уведомление: **«База знаний проиндексирована»** [OK]
6. Обновить дату на странице.
7. Ошибка → уведомление с текстом ошибки.

### 4.5 Загрузка страницы

При открытии страницы → `GET /kb/status` → отобразить дату последнего обновления и состояние.

## 5. Файловая структура и бэкапы

```
kb/
├── KB.pdf           ← текущий файл базы знаний
└── KB_backup.pdf    ← предыдущая версия (1 бэкап)
```

Правила:
- При загрузке нового файла: `KB.pdf` → `KB_backup.pdf` (перезапись), новый файл → `KB.pdf`.
- Хранится **ровно 1** бэкап.
- Бэкап нужен для возможности отката при плохом файле.

## 7. Конкурентность и безопасность

### 7.1 Lock переиндексации

Глобальный `asyncio.Lock` — не позволяет запустить две индексации одновременно. При попытке повторного запуска → `409 Conflict`.

### 7.2 Бесшовная переиндексация

Пока идёт индексация, бот продолжает работать со старой коллекцией Qdrant (через alias `kb_current`). Alias переключается на новую коллекцию только после полной загрузки. Пользователи не ощущают простоя.

### 7.3 Обновление BM25 индекса

После переиндексации Qdrant необходимо пересоздать `bm25_index` в памяти (глобальная переменная). Иначе sparse-поиск будет использовать устаревший словарь.

### 7.4 Валидация PDF

Четыре уровня проверки файла:
1. **Фронт:** FilePicker `accept=".pdf"` + JS-проверка размера.
2. **Сервер, MIME:** заголовок `Content-Type: application/pdf`.
3. **Сервер, magic bytes:** первые байты файла содержат `%PDF`.
4. **Сервер, читаемость:** `pdfplumber.open()` без ошибок.

## 10. Docker

### Volumes

Для персистентности `kb/` при деплое без bind mount добавить volume:

```yaml
# docker-compose.yml
services:
  app:
    volumes:
      - kb_data:/app/kb
      ...
volumes:
  kb_data:
```

### Порты

Новых портов не требуется — всё через существующий `8000`.
